# Промпт для нового чату: 3D-конструктор

Проєкт Grazia (D:\МЕБЕЛЬ GRAZIA\grazia.kh.ua). Прочитай AGENTS.md/CLAUDE.md, README, HANDOFF.md, DECISIONS.md і node_modules/next/dist/docs перед кодом.

Завдання: переробити наявний 3D-конструктор меблів. Зараз він у src/app/home-client.tsx (Canvas на @react-three/fiber, моделі з boxGeometry). Ліди йдуть через /api/telegram і приходять лише текстом з hex-кольорами - менеджер не бачить, що зібрав клієнт.

Ціль:
1. Винести конструктор в окремий компонент (src/components/configurator/*) з lazy-завантаженням (next/dynamic, ssr:false) - three.js не повинен потрапляти в початковий бандл головної.
2. Реалістичні параметричні модулі: корпус з товщиною ДСП 16/18 мм, цоколь, фасади із зазором 2-3 мм, ручки (рейлінг / профіль / без ручок), стільниця з виступом, верхні та нижні модулі, пенал, кутовий модуль. Розміри в мм, задає користувач (ширина стіни, конфігурація: пряма / кутова / П-подібна).
3. Матеріали з назвами, а не hex: каталог у конфіг-файлі (назва, код, колір, глянець/мат, roughness/metalness). У ліді - назва і код матеріалу.
4. Світло: мʼяке студійне (HemisphereLight + Directional з тінями, Environment preset), без важких постобробок; на мобільних знижувати dpr і вимикати тіні; frameloop="demand".
5. Макет у Telegram: Canvas з gl={{ preserveDrawingBuffer: true }}; при сабміті 2 знімки (фронт і 3/4) через gl.domElement.toBlob, JPEG ~1600px; multipart/form-data на /api/telegram; на сервері sendMediaGroup з фото і підписом-специфікацією (розміри, модулі, матеріали, ручки, стільниця, телефон). Токен лише на сервері. Обмеження розміру файлу, валідація, rate-limit. Не ламати наявну гілку source:'project' ("Хочу так само") у /api/telegram.
6. UX: покроково (Розміри -> Конфігурація -> Фасади -> Ручки -> Стільниця -> Контакти), кнопка "Отримати прорахунок", зрозумілі стани помилок/успіху. Дотримуватися /topics/ui-ux-standards з памʼяті.
7. Швидкість головної (зараз фризить): глобус/мапу (Mapbox) і будь-які важкі блоки нижче першого екрана завантажувати лише коли до них доскролили (IntersectionObserver + next/dynamic). Виміряти до/після: Lighthouse mobile, TBT та LCP головної, результат записати в HANDOFF.md.

Правила: мінімальні зміни поза конструктором; без заглушок і вигаданих даних; не оновлювати пакети без дозволу. Перед кодом - список файлів, потік даних, побічні ефекти. Після: npm run build і lint, перевірити, що в Telegram приходять фото (тестовий чат), оновити HANDOFF.md і DECISIONS.md.
